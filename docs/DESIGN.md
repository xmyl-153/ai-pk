# 设计思路

> 这份文档回答一个问题：**为什么是这么设计的，而不是再做一个榜单。**

## 0. 起点：三个让人不信任现有评测的事实

1. **官方跑分与实际体验脱节。** 同一个分数段里，P90 耗时能差 12 倍、
   单任务 token 差 3.8 倍（见 [`FINDINGS.md`](FINDINGS.md) 的实测数字）。
   跑分不测"等得烦不烦、烧不烧钱、绕不绕圈"。
2. **静态题库会被污染。** SWE-rebench（NeurIPS 2025）实测：同一批模型在
   SWE-bench Verified 上 39.7%，在去污染的 SWE-rebench 上只有 21.3% ——
   18.4 个百分点的差距来自数据泄漏，不是能力
   （[论文笔记](https://en.papernotes.org/NeurIPS2025/code_intelligence/swe-rebench_an_automated_pipeline_for_task_collection_and_decontaminated_evaluat/)）。
3. **harness（壳子）是隐藏变量。** Claw-SWE-Bench（2026）在同一批模型上实测：
   模型选择让 Pass@1 变动 29.4pp，**harness 选择变动 27.4pp**
   （[arXiv:2606.12344](https://arxiv.org/pdf/2606.12344v1.pdf)）。
   而绝大多数榜单把 harness 当常量、藏在"模型分数"背后。

## 1. 三条设计公理

### 公理 1：能被背下来的题不用 → 运行时程序化生成

题目实例由 seed 派生，答案由参考实现**现场算出来**：

- 生成器是代码，不是题库文件 → 没有可背的答案表
- 每个实例带 seed，任何人可复现 → **可复现 ≠ 可背**
- 每个族埋"同型陷阱"（约束条件每轮都换）→ 背题型的模型会当场栽

### 公理 2：能用代码判的绝不请裁判 → 代码 oracle 优先

判定优先级：**代码 oracle ≫ LLM 裁判**。

- 约束满足 / 单元测试 / 精确比对 → 代码判，二值、无争议、免费、可复现
- 只有开放文本（改写质量）才用裁判，且必须**交换位置评两遍**（消除位置偏置）
  并报告翻转率与无效率 → 见 [`FINDINGS.md`](FINDINGS.md) 第 4 节的实测：这条不是形式主义
- **判"改了几行"要看工作区快照**，不能看模型自称的 diff（`mindiff` 族）

### 公理 3：harness 不是噪声，是被测量对象

同一模型换壳子，行为差异可以大到改变结论。所以：

- Phase A：冻结一套提示词 + 工具协议 + 轮数上限，所有模型跑同一套 → 测"模型裸实力"
- 同一模型跑多套 profile（`frozen-v1` / `tools-off` / `flaky-tools` / `verbose-style`）
  → 出"harness 敏感度"
- Phase B：把**真实 CLI**（Codex CLI 等）包成同一个接口 → 用同一批任务、同一个 oracle 比
  （`aipk/harness.py::ExternalHarness`，`python -m aipk external`）

## 2. 第四条公理（做这个项目最大的收获）：测量装置自身要被测

前三条是"怎么测模型"，第四条是"怎么保证你没测错"：

> **每一次"某个模型表现异常差"，查下去都可能是我自己的测量代码有问题。**

这条不是口号，是 21 次事故的总结（全部写进了
[`MEASUREMENT_DEFECTS.md`](MEASUREMENT_DEFECTS.md) 与 `tests/test_measurement.py`）：
不限速被 429 打成假 0 分、用字符串比 JSON 导致 10 个模型全被冤枉、
题目自己给错答案、裁判"没判出来"被记成平局、多裁判重评的判决键少了模型维度……

工程上的落地：

- `tests/test_measurement.py`：**防测量错误的回归测试**（这个项目的免疫系统）
- `python -m aipk selfcheck`：每个族的 oracle 自洽检查（"对的不能被判错"）
- `python -m aipk demo`：**不需要 API key** 的端到端自检（满分机器人应 100% 通过，
  错答机器人应 0% 通过）—— 花了钱才发现装置坏了是最贵的一种失败
- 报告里把不确定性顶到台面上：置信区间、权重敏感性、pass^k、族内子检查、裁判审计

## 3. 五层结构

```
① 任务生成    aipk/tasks/fNN_*.py   程序化生成 + 参考实现 + oracle + 埋坑
      ↓
② 冻结执行    aipk/harness.py       多轮 agent 循环、4 个工具、故障注入、
                                    分阶段任务、仓库落盘、工作区快照
      ↓        aipk/scripted.py      离线满分机器人（无 key 自检用）
      ↓        ExternalHarness       Phase B：真实 CLI 当壳子
      ↓
③ 判定        grade.py / tasks     代码 oracle 优先；开放题才走盲评（位置去偏 + 审计）
      ↓
④ 指标        aipk/metrics.py       Wilson CI / pass^k / 一致性 / 综合分 /
                                    harness 敏感度 / 饱和度诊断 / 族内子检查
      ↓
⑤ 报告        aipk/report.py        HTML + Markdown + summary.json（原始证据可复算）
```

## 4. 反套利：每个族都埋了坑

| 族 | 埋的坑（想套利的人会栽在哪） |
|---|---|
| `constraint` 约束排班 | 生成 200 次才留一个"唯一解"实例；乱填必撞约束 |
| `toolchain` 工具链跟随 | 有引用不存在的文件、有从根不可达的文件（"全读一遍"必错） |
| `cascade` 级联调试 | 6 类隐蔽 bug；**真跑**模型给的修复代码再判 |
| `compliance` 硬格式合规 | 行首两字不能重复 + 字数上限 + 禁用词，且可解性由构造保证 |
| `multiturn` 需求变更跟随 | 中途推翻上一条规则，旧答案会混进来 |
| `longcontext` 长文规则应用 | 附录不算正文、作废记录、其他区域干扰 |
| `writing` 找错改写 | 8 组"看起来对但关键点反了"的技术陈述 |
| `repofix` 小仓库调试 | 多文件仓库 + **误导性注释** + 必须真跑 + 必须算数值 |
| `longstate` 长程状态维护 | 自相矛盾的操作、多轮累积误差、键集合变化 |
| `premise` 前提辨识 | 三种情形互为例题：一律说"前提错"或一律说"前提对"都会当场挂 |
| `mindiff` 最小 diff | 没用的 import、该改名的 TODO、发布流水线的格式化脚本、可篡改的自测 |
| `decay` 长会话一致性 | 另一个项目的**同名字段不同值**（串台引信）+ 自报首答必须属实 |

## 5. 权威性边界（写进报告，不是免责声明）

本项目只支持这样的结论：

- ✅「在 seed=X、配置=Y、时间=T 的这次运行中，系统 Z 的表现是……」
- ✅ 相对排名 + 置信区间 + 可复现的失败证据
- ❌ **不**声称"模型 X 整体比 Y 强"—— 任务分布是人选的，选择即偏见
- ❌ **不**给绝对智力分

四条对策（都做进了代码，不要削弱）：

1. 原始证据全落盘（每轮 transcript / 工具调用 / 用量 / 错误），任何人可复算
2. 权重敏感性分析：换权重就翻转的名次，明说"这几位差不多"
3. 多 replicate：报 pass^k 与方差，不报均值孤点
4. 裁判可审计：先标定再用，报位置翻转率、无效率、判平率
