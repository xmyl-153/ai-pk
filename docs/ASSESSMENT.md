# 这套设计有效吗？能跟上新模型吗？

> 直接回答，先给结论，再给证据。写这份文档的原则和项目本身一样：
> **只说自己测到的，测不到的就说测不到。**

## 一、一句话结论

| 问题 | 回答 |
|---|---|
| 作为**榜单**（谁更强）？ | ❌ **不成立**。正确率全面饱和；唯一还有区分度的维度（开放式质量）靠 LLM 裁判，而裁判噪声大到会改变名次。 |
| 作为**测量台**（它到底多少钱、多慢、多稳、换个壳子差多少）？ | ✅ **成立且稀缺**。这些数字官方跑分永远不给，而且我们测出了 12 倍耗时差、5.8 倍壳子成本差。 |
| 作为**测量方法论的载体**？ | ✅ **最有价值的部分**。20 个测量缺陷的清单 + 回归测试，比任何排名都耐用。 |
| 能不能**跟上新模型**？ | 🟡 **能测，但会一直报"又满了"**。新模型一接入就能测，但正确率维度会继续饱和 —— 区分度必须靠**升级任务**和**成本/行为维度**，不是靠等模型变弱。 |

## 二、"作为榜单不成立"不是猜的，是我们自己测出来的

1. **正确率饱和**：13 个族、10 个模型、900+ 次运行，成功率 90.5%~100%，
   95% 置信区间两两重叠；连刻意叠了四层难度的 `repofix` 也是 3/3 打穿。
2. **方差维度也饱和**：`temperature` 从 0 提到 0.7，180 次运行里正确性翻转 **0%**、
   实质漂移 **0%**（结构化任务）。
3. **唯一还能分开的是开放式质量**，但：
   - 换个裁判，名次就变：裁判之间平均 **Kendall τ = 0.467**；
     longcat-2.0 的分数在不同裁判手里是 **0.167 ~ 1.000**
   - 这不是我们独有的问题：*Nine Judges, Two Effective Votes*（2026）实测 9 个裁判
     只提供约 **2 票**的独立信息量，**加裁判没用**（错误高度相关）
   - 而且裁判"标定通过"不等于实战无偏：标定题翻转率 0%，实战 **27.2%**
     （*Reliability without Validity* 在 54 万次判决上复现了同一现象）

**所以：如果目标是"排出谁第一"，这个项目（以及任何单点榜单）都给不出可信答案。**
诚实的说法是"这几位在统计上分不出高下"。

## 三、但它作为"测量台"确实解决了真问题

这些是官方跑分、静态榜单都给不出的数字，而且都是可复算的：

| 我们测出来的 | 为什么重要 |
|---|---|
| P90 耗时差 **12.2×**（57.5s vs 702.2s） | 正确率并列第一的两个模型，一个秒回、一个让你等 12 分钟 |
| 单任务 token 差 **3.8×**、reasoning 占比差 **8×** | 同样的活，账单差几倍 |
| 换壳子（真实 CLI）成本差 **5.8×**、耗时 **2.9×**，质量打平 | 你花的钱有一大半花在"壳子"上，而榜单不告诉你 |
| `temperature=0` **并不确定**（6 次调用出 3 种答案） | 推翻了"贪心=可复现"这个几乎所有评测的隐含假设 |
| 结构化任务实质漂移 0% / 开放式任务 **100%** | 想测稳定性，得先选对任务类型，否则测了个空 |
| 长会话族的"中间任务全对"只有 **87%** | 正确率折成 0/1 之后，这类信号就被丢掉了 |

**而且这套东西的价值不依赖"排行榜能不能用"**：
它是**回归测试台** —— 你换模型、换提示词、换壳子、换网关之后，
"成功率有没有掉、成本涨了多少、故障恢复还灵不灵"是可测的。
这正是 SWE-rebench（NeurIPS 2025）选择的方向：不追榜单，做**持续更新的去污染回归集**。

## 四、能不能跟上新模型？分三种"新"

| 新在哪 | 这套设计的表现 | 原因 |
|---|---|---|
| **新模型发布**（加一行 roster） | ✅ 立刻能测，不用改代码 | 任务是程序化生成的，没有"题库过期"问题；`roster` 是数据不是代码 |
| **模型整体变强** | 🟡 正确率维度会持续饱和 | 区分度会**衰减**：这是所有静态难度评测的共同命运。对策是**升级任务**（更长链路、真实仓库、多文件改动、开放式），而不是等 |
| **交互形态在变**（agent CLI、工具链、多 agent） | ✅ 已经提前接上 | Phase B 把"壳子"做成一等被测对象：同一批任务、同一个 oracle，换壳子直接比。Claw-SWE-Bench 独立证明这是第一位的变量（harness 影响 27.4pp） |

**关键判断：这套设计的"耐久性"不在于题目多难，而在于它测的是**结构性的东西**——
成本、延迟、稳定性、故障恢复、壳子敏感度。这些不会因为模型变聪明而消失，
反而会因为"大家都会做题"而变成唯一的区分度。

## 五、和同类开源项目的对照（以及我们从它们那儿学到的）

| 项目 | 它做到的事 | 我们的差异 |
|---|---|---|
| **SWE-bench / SWE-rebench**（[笔记](https://en.papernotes.org/NeurIPS2025/code_intelligence/swe-rebench_an_automated_pipeline_for_task_collection_and_decontaminated_evaluat/)） | 从真实 PR 自动挖 2.1 万条可执行任务 + 去污染 + 统一 scaffold + 多次运行报 pass@5 | 我们走"程序化生成"而不是"挖真实 PR"：更小、无依赖、可离线复算；代价是任务更"人造" |
| **Terminal-Bench / Harbor**（[repo](https://github.com/harbor-framework/terminal-bench)） | 持续更新、带版本、社区贡献任务、oracle 自检（`--agent oracle`）的基准 | 我们**照抄了它的 oracle 自检思路**：`python -m aipk demo` 就是"零成本 oracle 跑"，并要求满分机器人 100% 通过 |
| **Claw-SWE-Bench**（[arXiv:2606.12344](https://arxiv.org/pdf/2606.12344v1.pdf)） | 把 harness 当**受控变量**：模型换 → 29.4pp，壳子换 → 27.4pp；报总成本与缓存命中 | 我们的 Phase B 是同一件事的更小规模实现；它证明了这条路是对的 |
| **agent-harness**（[repo](https://p.rst.im/q/github.com/asp53826/agent-harness)） | 沙箱 + 12 个程序化判定任务 + **默认不需要 API key** 就能跑（脚本化模型） | 我们**借鉴了"无 key 可跑"**：`aipk/scripted.py` + `aipk demo`；这是开源门槛问题，不是技术问题 |
| **LLM-as-a-Judge 研究**（[arXiv:2605.29800](https://arxiv.org/html/2605.29800)、[arXiv:2606.19544](https://arxiv.org/abs/2606.19544)） | 量化裁判的位置偏置、相关性、有效票数 | 我们把它们的结论做成了**工程约束**：先标定再用、交换位置双评、报翻转率、多裁判+分数区间 |

**我们的空档位**：把"**测量装置自身要被测**"当成第一等公民的**自托管小测量台**。
别人的基准关心"任务够不够难、够不够真"，我们额外关心
"**我这次测出来的数字，是不是我自己的测量代码造成的**"——
20 个缺陷清单就是这件事的产物，也是这个项目最该被别人拿走的东西。

## 六、诚实的能力边界（不吹的部分）

- **样本小**：3 实例/族、27 次/模型。要报更硬的结论需要 ≥10 实例/族（成本按比例涨）。
- **任务是人选的**：选择即偏见，我们不说"模型 X 整体更强"。
- **裁判是瓶颈**：开放式任务的评估质量受限于 LLM 裁判，而裁判之间有强相关误差；
  真正要硬结论，得有人类标注或可验证的代理指标。
- **Phase B 样本薄**：只有 6 组配对，且无法完全隔离"壳子"与"供给"。
- **不能替代真实用户反馈**：它测的是"在给定任务分布下的表现"，不是"好不好用"。

## 七、下一步该做什么（按价值排序）

1. **把"成本/行为"维度做成一等公民**：token 经济性、上下文重发、长程耗散、故障恢复 —— 这些是饱和时代的区分度。
2. **开放式任务 + 人类标注锚点**：既然裁判会漂，就用少量人工标注去校准裁判，而不是加裁判。
3. **升级任务链路**：10+ 步的真实多文件仓库任务、跨会话长任务。
4. **接更多真实壳子**（Claude Code 等）：把 harness 敏感度做成常规维度。
5. **规模化**：≥10 实例/族，让置信区间真正有用。
